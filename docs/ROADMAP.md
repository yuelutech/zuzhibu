## 做法

- Python 只用标准库；桌面外壳和界面用 Electron 及其前端工具（2026-10-21 起）；不建数据库、队列和后台服务。
- 采集只用免费能力和已有工具：公开数据集、官网、联邦公报、证券交易委员会申报，加维护者本机已登录的 Codex CLI。
- 写回规则写在代码里（`zuzhibu/personnel.py`），模型只负责取证和核查；放行 fail-closed。
- 每轮推进后更新 PRODUCT.md 第十二节“功能现状”和本表的状态列。

## 云会话与本机分工

云会话只能拿到本仓库里的代码，拿不到本机文件、字体、办公软件、Codex 登录。

- 云会话可做：纯代码和测试、界面、文档、用假数据测的流水线代码。
- 必须本机做：Codex 实跑（一局更新、四局重核、各局建简历），计划任务，字体与办公软件核版式，安装包构建与试装。
- 给云会话的要求写进 `docs/cloud-tasks/`，以 PRODUCT.md 为依据。

## 暂缓

秘书局、宣传教育局、公众号排版：v0.1 试跑成果保留（代码、写法规范、试跑判断单），不再投入开发。

## 公开前检查

1. 字体：全库没有 .ttf、.otf、.ttc 文件。
2. 标识：全库没有任何第三方 App 的名称、标识和截图。
3. 样本：shared/samples 里私有阶段放的真实样本全部清理；历史提交里有真实人物样张的，重建仓库历史。人物资料库（data/）只收有公开来源的公众人物公职信息。
4. 密钥：全部历史扫描无凭据。
5. 第三方代码：没有非商用许可、无许可证或 GPL 项目的文件。
6. 语料：没有受版权保护的原文全文；来源摘录只留短句。
7. 表述：README、界面和输出物的文案和人民网一样严肃，不出现没意义的标签和说明：界面不显示分级、写法检查、资料日期、条数一类标签，导出物只留正文；只在 README 和“我的”页最下面各写一句“本项目为戏仿项目，与任何党政机关无关。”
8. 安全：写法规范不含联网指令和自动执行脚本。
9. 后端：README 写明不共享账号、不代跑。
10. 数据分发：公开仓库的地址不是 `yuelutech/zuzhibu` 时，先改 `zuzhibu/datasync.py` 的 `DEFAULT_SOURCES`，一局更新也改推到公开仓库；转公开后用默认地址实取一次（`python -m zuzhibu.datasync check --home 临时目录 --bundled data`），应显示“已更新”或“已是最新”；再从公开仓库构建安装包、试装一次（`python -m tools.installer.smoke`），把 `.msi` 和 `.sha256` 发到 GitHub Releases。
