- AI政见·组织部是 Yuelu Tech 旗下“AI政见”品牌的软件产品。
- 交付目标：在 Yuelu Tech 的 GitHub 上开源，提供可安装、可实际使用的桌面软件。

## 二、两个核心功能

1. 人事动态：发现并核实人事变动（流水线在 `bureaus/dispatch/`，内部称一局）。维护者每月更新一次，随仓库发布；用户想更勤，用自己的 AI API、自己的额度随时更新。
2. 干部简历资料库：五栏名单里的人物资料，供查看和检索。

两者联动：核实的每条动态都写回对应人物的简历（第四节）。界面只围绕名单、人物简历和人事动态展开。

人事动态公开规则（2026-10-22 定，统一由 `zuzhibu/renmian.py` 生成，界面和立即更新都调用它）：

- 前台只回答两件事：谁任什么职务，谁不再担任什么职务。不设事件类型标签和筛选。标题用“某某任某职”“某某不再担任某职”“某机构人事调整”这类写法。
- 中国企业（总部在中国的企业，含港澳台地区）不收：涉及其职务的动态不写回、不公开，研究提示词里也写明（维护者 2026-10-23 定；常见企业列在 `zuzhibu/bureaus.py` 的 `CHINESE_COMPANIES`）。
- 公开的是已经落地的结果：到任、就任、宣誓、代理、调任生效、离任、逝世，以及参议院确认。提名、生效日在未来的宣布、媒体预测只留在后台核验，不公开，也不据此更换名单上的人。
- 维护者手定（优先于其他说法，模块里留开关）：名单外人员的动态也公开，正文只写姓名，不链接，不建人物页，搜不到；参议院同一天确认的一批人合成一篇，如“美国参议院确认一批人事任命”。
- 同一次任职只出一项结果。参议院已确认的人后来宣誓到任，只更新简历的起始日期，不再单独成篇。确有新的职务变化（如由代理转为正式），算新的一项。
- 合篇只合同一天、同一决定主体的同类事项。不同公司、不同机构碰巧同一天换人，不合篇。合篇按任职、不再担任分段，没有对应事项的段不写。
- 正文能一句说清就一句，写时间、决定主体和职务变化，不写背景、评价、程序流水账。代理不写成正式任命，辞职不写成免职，选举产生的职务不编造任命机关，来源只证明职务变化的不补造决定机关。正文用结构化字段按固定模板生成，不调 AI。
- 事件日期、来源发布日期、本机采集日期分开存放。前台的“发布时间”用事件日期，精确到日；事件日期只知道到月的不公开，留在后台（维护者 2026-10-22 定）。合篇时每项事实各带自己的来源。
- 后台证据、程序记录、日期精度和核查状态全部保留，前台只出结果。

- 名单文件格式：`{"id", "title", "groups": [{"title", "note", "style", "members": [{"person", "post"}]}]}`。`style` 取 `lead`（单人大像）、`row`（一排）、`grid`（网格）、`list`（只列姓名和职务）；`members` 已按显示顺序排好，`post` 是像下显示的职务；国会成员另带 `party`、`state`、`district`。名单文件随数据分发。
- 名单随每月更新复核：名单里的人离任、名单上的职务换人时，由维护者改名单文件。使用者立即更新时，核实落地的任免可让本机名单先换人（规则见第七节），维护者数据换新后按合并规则处理。
- 标准像：名单里每个人都必须有照片，一律是蓝白渐变底的 3:4 头肩像，600×800。抠图、换底在仓库外用维护者本机的工具做（仓库的 Python 只用标准库），仓库只放成品；来源和许可照旧登记原图，注明“已换蓝白渐变底”。
- 人物记录的 `bureau` 字段（ai、whitehouse、congress、military、justice、retired）留在数据里，供一局判定收录范围和写回，界面不显示。

## 四、动态与简历联动

下面的“局”是数据里的内部归属（`bureau`），界面不显示；转入七局的人即离任人物，界面上不再出现。

一局发现并核实人事变动后，同步更新对应人物的四项：现任职务、履历记录、资料更新时间、所属局。维护者的每月更新和用户自带 API 的主动更新执行同一套规则，规则写在代码里，不交给模型裁量。

1. 正常调任：原职务从现任职务移出，履历里对应条目写上止时间；新职务进现任职务，履历新增条目；按新的主要职务重新判定所属局。
2. 转入七局：只有同时满足下面三条才转入。
   - 记录里移出这项职务后，再没有其他现任职务。
   - 核实结果明确写着此人没有其他现职（`other_current_roles` 为空）。
   - 核实结果明确写着没有公布新任命（`new_appointment` 为空）。

   三条有一条不满足，就不转局，动态标“待核”，在界面上提示人工核对。这样避免把正常调任、只免去一项兼职的人误转进七局。
3. 七局人物重新任职：按新职务转入对应业务局。
4. 转局时保留完整履历、来源和历史人事动态，沿用同一份人物记录；每次转局在 `bureau_history` 记一条（原局、新局、日期、所据动态、原因）。
5. 新任职务不在任何业务局范围内：二局人物在企业之间调动（含离职创业）仍归二局；其他人（例如离开政府去了非科技企业）不转七局，暂留原局，动态标“待定”，由维护者定归属。
6. 宣布任命但未到任（提名、参议院确认、宣布）：新职务写进现任职务和履历，任职状态写“提名人选”或“候任”，首段、现任段显示“××提名人选”“候任××”；未到任的职务不改所属局。到任时这一条改成正式职务，起始日期取到任日。参议院确认之后有一级来源给出宣誓日的，就是到任。宣布时生效日还没到的，按宣布记（动态日期取宣布日），现任和履历都不改，职务记为拟任（人物记录的 `planned_roles`），首段末写“拟于某年某月某日任××”；到期后由每月更新复核是否到任。
7. 离任且没有新职：首段末写“曾任××”；逝世的记卒年，姓名后括注生卒年月。人物状态（在任、提名人选、候任、离任、逝世）随写回更新。
8. 写回之后重排履历、重算日期粒度和图卡类型，用事实包 schema 校验；不通过就不写，动态标“写回失败”。
9. 写法依据 `rules/cadre.md` 第 8 节第 7 条（2026-10-17 简历字段纪律定稿）。

## 五、人物归属

## 六、数据

全部数据在仓库的 `data/` 目录，纯 JSON，人物和动态各一个文件，便于逐条审阅和比对。

| 路径 | 内容 |
|---|---|
| `data/people/<人物编号>.json` | 人物记录：一人一份，全局唯一 |
| `data/events/<年-月>/<动态编号>.json` | 人事动态：一条一份 |
| `data/meta.json` | 数据版本、各局实际资料截止日期、最近一次一局更新（字段名沿用 `daily`） |
| `data/manifest.json` | 数据清单：`data/` 下每个文件的 SHA-256 和字节数、生成时间、数据日期；软件联网按它增量更新、逐个校验（`zuzhibu/datasync.py`），提交数据前用 `python -m zuzhibu.datasync manifest` 重算 |

人物记录：

| 字段 | 内容 |
|---|---|
| `id` | 人物编号，小写英文与连字符，建立后不改 |
| `name_zh`、`name_en` | 中文名（译名表）、英文名 |
| `bureau`、`also_in` | 所属局、另行展示的局 |
| `tier` | 分级，见下 |
| `ids` | 外部编号（国会 bioguide、维基数据等） |
| `resume` | 简历事实包条目（`shared/schema/bundle.schema.json` 的 cadreItem），含来源表 |
| `data_cutoff` | 实际资料截止日期：简历事实最近一次核实的日期 |
| `updated_at` | 资料更新时间：记录最近一次改动的日期 |
| `events` | 引用此人的动态编号 |
| `bureau_history` | 历次归属 |

分级（说明资料从哪来、核到什么程度）：

| 分级 | 含义 |
|---|---|
| `gold` | 金标：逐人取证、人工审定 |
| `reverified` | 已重核：本机 Codex 两次会话取证和核查都通过 |
| `draft` | 底稿：未核实的初稿 |
| `seed` | 名册：只有官方来源的现任职务，简历待建 |
| `held` | 搁置：核查未通过，待人工处理 |

能不能输出只看完整简历卡门槛（`rules/cadre.md` 第 4 节第 6 条），两条都满足才能输出：
- 五项齐全：姓名、性别、国籍、出生年、参加工作年；出生年和参加工作年有来源，或者按登记的推测规则从有来源的事实推出来；
- 现任职务有一级来源（离任人物看最后的主线职务）。来源等级按 `rules/cadre.md` 第 4 节：一级是官网、年报、学校官网、政府和军队网站，美国另加联邦选举委员会、congress-legislators、Bioguide、EDGAR；二级是权威媒体、权威百科、本人署名的公开自述；维基只作线索。事实包没标等级的，`zuzhibu/sources.py` 按链接判定。

过不了门槛的留在 `seed` 一类，只能查看。程序算出的图卡类型和日期粒度存进事实包的 `card_type`、`date_granularity` 供审。

动态记录：编号、类别（任命、离任、调任、提名、确认、代理、逝世）、人物编号与姓名、原职务、新职务、宣布日期、生效日期、仍担任的其他现职、是否已公布新任命、来源（链接、标题、发布日期、查阅日期、原文摘录）、核实结果（通过或待核、核实方式、日期）、写回结果（改了什么、转局前后）。界面里公开的任免结果（是否公开、去重、合篇、标题、正文、按事实列的来源）统一由 `zuzhibu/renmian.py` 按结构化字段和固定模板生成，规则见第三节；职务写法沿用 `zuzhibu/headline.py`。研究、核查会话写的标题和摘要只作内部记录，不在界面和输出里显示。

纪律沿用 aipolis `rules/` 母本（cadre.md 含美国附则，country_rw.md 是卢旺达附则；本仓库不带副本，四局重核从本机设置给的规则目录读，要点写在 `shared/skills/cadre-resume/SKILL.md`）：只写有可核验来源的事实，除五项必写外缺项留空，不编造；中文译名以 `shared/glossary/` 译名表 v1.4 为准，表外专名按使用说明补录，复核清单记一笔。

## 七、更新机制

- 每月更新（维护者本机）：Windows 计划任务每月 1 日 08:00 运行一次一局流水线 `bureaus/dispatch/run.py`（2026-10-21 起由每天改为每月，省维护者的额度），窗口从上次更新的截止日到当天：
  1. 采集候选线索（免费来源，程序抓取）。
  2. 研究：本机已登录的 Codex CLI 联网逐条取证，输出结构化动态。
  3. 核查：逐条核（2026-10-21 起）——先程序取网页核对一级来源摘录，人物、职务、类别、日期都在来源里的放行；过不了的一次开一个 Codex 核查会话只核一条，重新打开来源逐字段核对，会话里没打开过的来源不算核实，没明确通过的一律搁置。
  4. 写回：按第四节规则写回人物记录，校验通过才落盘。
  5. 刷新商界市值：写回之后用同一个后端查一次名单里上市公司的收盘市值（`bureaus/dispatch/marketcap.py`，规则见第三节），查不齐或核不过整份不写；结果只记日志和运行记录，不影响这次更新算不算完成。使用者立即更新也一样，用使用者自己的接口。
- 免费来源：congress-legislators 公开数据（国会议员变动）、各机构官网与新闻稿、联邦公报、美国证券交易委员会 EDGAR 申报（上市公司高管变动）、官方 RSS。只用免费能力和已有工具，不买数据服务。
- 用户自带 AI API：想比每月更勤的用户在设置里填自己的 AI 接口，用自己的额度。能用的是带联网检索工具的两类接口：OpenAI 兼容接口（Responses 接口的 web_search 工具）、Anthropic 接口（Messages 接口的 web_search、web_fetch 工具），接口地址、模型名可改；只能对话、没有联网检索的接口不能开更新。“检测接口”只检索 1 次，看这个接口和模型能不能联网，结果照审定的文案显示。点设置里的“立即更新”时，用使用者的接口走同一条流水线（`bureaus/dispatch/run.py --backend api --since-last`，后端 `shared/backends/ai_api.py`）：先检测联网检索；窗口从数据截止日到当天（最长 62 天，超过 7 天研究会话最少检索 40 次）；研究、核查两次会话都联网，放行（fail-closed，核查不过的搁置）和写回规则与维护者完全相同；结果只写本机数据目录，不提交、不推送，状态记在 `meta.json` 的 `user_update`，不顶替维护者的更新状态（`daily`）。普通用户不需要配置。软件不内置、不使用维护者的任何账号、密钥或 Codex 登录；没填接口而这台电脑上使用者自己登录了 Codex 时，“立即更新”用它（使用者自己的额度）。
- 立即更新的进度和停止（2026-10-22）：按 6 步报进度，进度条下方逐步显示维护者 10-21 审定的提示语（`zuzhibu/progress.py`）：连接接口（检测联网检索，重放本机更新）、查询公开信息（免费来源采集线索）、深度思考（研究会话按资料库五栏分五组，显示“白宫 2/5”）、逐条核实（“第 3 条，共 12 条”）、获取简历（新任人员人数）、更新简历（写回的名单人物人数）。商界市值在第 6 步写回之后接着刷新，不另报一步，完成提示不加字。进行中按钮变为“停止更新”：不再开新会话，接口上正在跑的会话取消，已核实的照样写回，提示“更新已停止。已核实的 n 条人事动态已保存。”接口密钥、额度、联网检索出问题时同样停下、写回已核实的，提示“更新未完成：接口额度不足。已核实的结果已保存。”一类。停下和未完成的这次不推进截止日，下次重查这段。停下时市值还没开始刷新的不刷新，刷新到一半的整份不写。完成时的“新增人事动态 n 条”和停止时的“已核实的 n 条”是人事动态栏目里新出现的稿件数（更新前后各取一次 `renmian.articles`，比对稿件编号），不按动态条数算；“更新简历 n 份”计实际写回的名单人物。本地接口：`POST /api/update` 开始，`GET /api/update` 读进度，`POST /api/update/stop` 停止；流水线写进度文件、看停止文件，都在软件本机目录的 `update\`。
- 名单换人与获取简历（2026-10-22）：立即更新核实的任免落地了（任命、调任到任或代理，生效日不晚于当天），名单上同一岗位是别人的，本机名单换人（`zuzhibu/rosterchange.py`）。两件事分开判断，宁可漏、不可错，漏了的由维护者每月复核：
  1. 是不是同一岗位：国会按实际议席（州、选区），商界按具体公司加首席执行官，其余按机构加职务名；只有职务名相同的，机构还要和这个位置现任的机构相同；代理和正式算同一岗位，副职、常务副职顶不了正职；一个位置写着两项职务的不认，交维护者。文字相似不算同一岗位。
  2. 有没有足够证据换掉现任：提名、参议院确认、生效日在未来的宣布不换（参议院确认可以公开，名单等到任再换）；正式到任、名单上这个写法只有一个位置的直接换；代理要有原任已离开的核实动态；同一写法有几个位置的（大法官、同州两名参议员），职称相同不能互相替换，只换有核实动态证明已离开的那一位，对不上或对上不止一位的不动。同一人由代理转为正式只改职务写法；代理的写“代理”，不写成正式。
  新任库里没有完整简历卡或照片的，用使用者自己的接口取标准简历（`bureaus/dispatch/resumes.py`）：研究、核查两次会话，照写法纪律逐字段取证、核对，过完整简历卡门槛和写法检查（cadre_lint）；另取机构官网上的本人照片，程序取网页核对照片在官网上。名单外的人不取简历，只在动态正文里出现。名单、人物记录、照片引用、这条动态一起写，中途出错全部退回原样；新任的简历或照片没取到、更新停下了、写入出错的，这一组都不写，不留半成品，留在本机更新目录下次立即更新接着办（简历最多取 3 次，取不到的交维护者每月复核名单）。原任移出名单，人物记录留着。
- 本机更新与维护者数据合并：立即更新写进的动态、取到的标准简历、名单变动另记在本机更新目录（`%LOCALAPPDATA%\zuzhibu\local`，`zuzhibu/localupdates.py`）。联网取到维护者的新数据、维护者改过的文件整份换掉时（数据分发换快照时，在新快照试读之前调 `localupdates.after_sync`），逐组重放。谁优先：维护者每月下发的数据是底本，同一件事以维护者为准；本机新核实、维护者还没有的，重放到底本上；维护者在本机这条之后另有变动的，不拿本机较早的消息去盖。
  - 动态：维护者已有同一条（同一人、同一类别、日期相差 7 天内）的以维护者为准；维护者数据里此人有更晚动态的不重放，标“待核”，免得拿旧消息盖掉新资料；其余按同一套写回规则重放；维护者没改过的人物不动。
  - 标准简历：维护者已有此人完整简历卡的用维护者的；没有这个人、或只有名册级资料的，装上本机取到的标准简历和官网照片。
  - 名单：维护者名单上这个位置已是新任的不动；已是第三人或没有这个位置的，以维护者为准；还是原任（维护者的数据还没跟上），而维护者数据里新任、原任都没有比本机这次更晚的动态、新任的人物记录够上名单的，把本机这处换人重放上去，维护者较旧的名单不会盖掉本机已核实的新任命；不满足的以维护者为准。
  - 同一组的动态、人物记录、名单一起写，出错全部退回，下次再放。重放不调模型、不联网，原件一直留在本机更新目录。
- 密钥：只存在用户本机的设置文件（`%APPDATA%\zuzhibu\settings.json`），只放在发给接口的请求头里，不进仓库、命令行、日志、过程记录和数据，不上传；接口报错时回显的密钥也隐去。本地接口只收本软件页面发来的同源请求；换接口类型或地址时清掉旧密钥，密钥只发往填它时的那个地址。
- 数据分发：维护者每月更新的数据随仓库发布（main 分支的 `data/`，提交前重算数据清单）。安装版软件启动时联网检查一次、开着时每天最多一次（默认 `https://raw.githubusercontent.com/yuelutech/zuzhibu/main/data/`，设置里可改地址、可关自动更新）：只读 GitHub 上的公开文件，不花任何人的 AI 额度；清单没变就不下载，变了只下载改过的文件，逐个核对 SHA-256，全部到齐、试读通过才切换；取不到（仓库公开前、断网）、校验不符、中断都继续用本机那份完整数据，不报错。只发 GET 请求，不带、不收集任何用户信息。从仓库运行时读仓库 `data/`，不联网取数。安装、升级、卸载和数据更新的做法见 [INSTALL.md](INSTALL.md)。

## 八、界面（2026-10-21 定，第二版改版中）

- 桌面外壳：Electron。不用系统标题栏，最小化、最大化、关闭由系统画在右上角，旁边一个三条线按钮，点开是“设置”“关于”。没有页脚。
  - 启动保护（2026-10-22）：“正在打开”页和本地服务同时启动。启动时页面进程或显卡进程崩溃，第一次先清显卡缓存重开；再崩就关闭显卡加速重开，并在本机设置 `local.json` 写 `"gpu": "off"`，以后直接关着开；还打不开就停下，提示重启电脑，可以打开日志文件夹。启动以后，页面进程一分钟内最多重新加载两次。所有异常写进 `shell.log`，不弹技术性报错。
  - 软件图标：维护者 2026-10-22 选定。红底，白色展翅海雕剪影，下方蓝带上三颗白星。海雕自画，不用美国国徽原图。
  - 设置：大模型接口（接口类型、地址、模型名称、密钥；保存、检测接口）、更新人事动态（立即更新、停止更新，进度条下方逐步显示六步，进度和提示语见第七节）。文字照维护者 2026-10-21 审定的文案稿。数据联网检查在后台自动进行。
  - 关于：版本、简介、声明（4 条）、开源声明（项目地址，“许可全文”“照片署名”两个链接）、友情链接（美国白宫等 10 个官网，用系统浏览器打开）；最下面一句“本项目为戏仿项目，与任何党政机关无关。”文字照审定的文案稿（`web/js/about.js`）。
- 导航六项：白宫、商界、国会、国防、司法、人事动态。默认首页是白宫。搜索只搜名单里的人。
- 名单页：照党政领导机构的方式，按职务层级逐级展示 3:4 标准像，像下写姓名和职务；分组和顺序见第三节。
- 人物页：只有标题（“××简历”）、标准像、标准简历（首段、现任、逐条经历）。不显示“履历”二字、相关动态、来源和导出入口。
- 人事动态：照共产党员网人事任免页（第三节）。标题由程序生成（第六节）。
- 视觉：参考求是网、人民网中国政要资料库等党政媒体网站，要精致：字体、留白、标准像网格、页面切换和悬停的过渡都要讲究，长名单滚动顺滑。只借版式和配色，不用这些网站的图片、徽标和文字（人事动态单篇的“人事任免”横图自制，750×230，红底白字）。不用任何第三方 App 的名称和标识。
- 字体（2026-10-22 维护者选定 B 套）：标题用思源宋体粗体，正文用朱雀仿宋，职务和小标题用霞鹜文楷，英文和数字用 Times New Roman。前三种是 SIL OFL 开源字体，构建安装包时从官方发布处下载，随包附许可证，不提交进仓库；Times New Roman 用系统已装的，不随包分发。本地服务从字体目录供给 /fonts/（环境变量 ZUZHIBU_FONTS、本机设置 local.json 的 fonts，否则程序目录下的 fonts\，安装版即 resources\pyapp\fonts\）。字体加载不到时如实降级到系统字体。
- 文案：和人民网一样严肃，不显示分级、核查状态、日期精度、更新时间、数据截至、条数一类标签和说明，不加 AI 生成标识。

## 十三、开源交付

- 许可：代码 Apache-2.0；写法规范、译名表、金标样本，以及人物资料库（`data/` 和各局的名册、事实包）的编排和中文撰写部分 CC BY-SA 4.0。来源摘录和人物照片不在这两种许可之内，按各自来源和许可（事实包来源表、`data/portraits/index.csv`）；仓库里只放公有领域和 CC BY、CC BY-SA 的照片，需要署名的在“关于”里集中署名。
- 转公开前按 `docs/ROADMAP.md` 的“公开前检查”逐项检查，结果记在 `docs/公开前检查.md`。
- 发布顺序（2026-10-22 定）：各分支集成、测试，装到维护者本机并建桌面快捷方式，维护者试用，改完反馈，维护者确认后再推送或发布。确认之前只在本机提交，不推送，不发正式版本，不对外宣传安装包。
- 软件只调用使用者本机自己登录的 Codex 或使用者自己的 API，不提供、不共享任何账号和密钥。
- 不代跑：维护者不替使用者运行检索、更新或简历生成，不提供在线服务；随仓库发布的每日更新数据由维护者在自己电脑上用自己的账号生成。
- 简历只写有可核验来源的事实。文案和人民网一样严肃，不出现没意义的标签和说明：界面不显示分级、写法检查、资料日期、条数一类标签，导出物只留正文；只在 README 和“关于”最下面各写一句“本项目为戏仿项目，与任何党政机关无关。”分级只给维护者用，不在界面和输出物里显示。
